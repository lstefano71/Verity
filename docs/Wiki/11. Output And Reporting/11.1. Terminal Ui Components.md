## Progress Bar Implementation

The application implements real-time progress tracking during file scanning and hash computation using Spectre.Console's Progress and Status components. The progress bar provides visual feedback on the verification process, showing both overall progress and per-file progress.

The implementation uses a two-phase approach: first reading the manifest and calculating total work, then processing files with progress updates. The `AnsiConsole.Progress()` method creates a multi-column progress display with task descriptions, progress bars, percentage completion, remaining time, and spinner indicators.

During file processing, the `VerificationService` raises `FileStarted` and `FileProgress` events that are handled to create and update progress tasks. The `FileStarted` event creates a new progress task for each file being verified, while `FileProgress` updates the current file's progress based on bytes read. When VSS mode is enabled, the `VssPathResolver` is used to resolve file paths to their snapshot equivalents before processing.

## Diagnostic Tables

The diagnostic tables display per-file verification results with color-coded status indicators to quickly identify issues. The tables are implemented using Spectre.Console's Table component and show problematic results (warnings and errors) with detailed information.

The implementation in `ResultsPresenter.RenderDiagnosticsTable()` creates a table with columns for status, file path, expected hash, actual hash, and details. Success results are not displayed in this table as they are summarized elsewhere. The table uses color coding:
- Yellow for warnings (e.g., "Missing metadata")
- Red for errors (e.g., "Hash mismatch", "File not found")

The table is only rendered when there are problematic results or when the `showTable` option is explicitly set to true. This prevents cluttering the output when all files verify successfully.

## Summary Statistics Panel

The summary statistics panel provides a comprehensive overview of the verification process, showing key metrics in a clean, organized format. The panel is implemented using Spectre.Console's Table component with no borders and hidden headers for a minimalist appearance.

The summary includes:
- Success count (green)
- Warning count with top issue breakdown (yellow)
- Error count with top issue breakdown (red)
- Total files processed (blue)
- Total bytes hashed (blue)
- Total time (cyan)
- Throughput (cyan)

The warning and error sections show the top three most common issues, with remaining issues grouped under "Other" for clarity. This helps users quickly identify patterns in verification problems without overwhelming them with details.


```csharp
var summaryTable = new Table()
    .NoBorder()
    .HideHeaders()
    .AddColumn(new TableColumn("Label").LeftAligned())
    .AddColumn(new TableColumn("Value").LeftAligned());

// Success total
summaryTable.AddRow("[green]Success[/]", $"{summary.SuccessCount:N0}");

// Warnings total and breakdown
summaryTable.AddRow("[yellow]Warnings[/]", $"{summary.WarningCount:N0}");
foreach (var (label, count) in GetTopDetailsGroups(
    summary.ProblematicResults.Where(r => r.Status == ResultStatus.Warning), "yellow")) {
    summaryTable.AddRow(label, $"{count:N0}");
}

// Errors total and breakdown
summaryTable.AddRow("[red]Errors[/]", $"{summary.ErrorCount:N0}");
foreach (var (label, count) in GetTopDetailsGroups(
    summary.ProblematicResults.Where(r => r.Status == ResultStatus.Error), "red")) {
    summaryTable.AddRow(label, $"{count:N0}");
}
```

## ResultsPresenter and Console Layout

The `ResultsPresenter` class manages the entire console layout, coordinating the display of headers, progress indicators, diagnostic tables, and summary statistics. It serves as the central component for terminal UI presentation.

The console layout follows a structured sequence:
1. Header panel with verification information
2. Progress indicators during processing
3. Completion message
4. Diagnostic table (if applicable)
5. Summary statistics table

The `ResultsPresenter` handles responsive design considerations by using Spectre.Console's built-in terminal size detection and adaptive rendering. Path abbreviations are implemented through `Utilities.AbbreviatePathForDisplay()` which truncates long paths by inserting ellipses in the middle, ensuring they fit within terminal width constraints.

## Event Handling and UI Updates

The UI updates are driven by events from the `VerificationService`, creating a clean separation between business logic and presentation. The event-driven architecture ensures thread-safe rendering through Spectre.Console's synchronization mechanisms.

Key events and their UI handling:
- `FileStarted`: Creates a new progress task for the file being processed
- `FileProgress`: Updates the progress task with current bytes read
- `VerificationComplete`: Triggers final result presentation

The event handling is implemented in the progress context using closures that capture the progress context. When a file starts processing, a new progress task is added to display per-file progress. The `Bag` property of the event arguments is used to store a reference to the progress task for later updates. When VSS mode is enabled, the `VssResolver` property is set on the `VerificationService` to ensure files are accessed through the snapshot.

```
csharp
verificationService.FileStarted += (sender, e) => {
    int padLen = 50;
    var safeRelPath = Utilities.AbbreviateAndPadPathForDisplay(e.Entry.RelativePath, padLen);
    e.Bag = ctx.AddTask(safeRelPath, maxValue: e.FileSize > 0 ? e.FileSize : 1);
};

verificationService.FileProgress += (sender, e) => {
    if (e.Bag is ProgressTask fileTask) {
        fileTask.Value = e.BytesRead;
    }
};

```

## Accessibility Considerations

The application incorporates several accessibility features to support users with different needs, particularly those who may have difficulty perceiving color differences.

Color usage follows a consistent scheme:
- Green for success (positive outcomes)
- Yellow for warnings (caution needed)
- Red for errors (critical issues)

While the primary visual indicator is color, the interface also uses text-based indicators and symbols to convey status information. The diagnostic table includes explicit status labels ("Warning", "Error") in addition to color coding. The summary table uses text labels like "Missing metadata", "Hash mismatch", and "File not found" which are meaningful even without color perception.

The `AbbreviatePathForDisplay` method helps users with cognitive load by truncating long paths, making it easier to scan results. The padding with '▪' characters in `AbbreviateAndPadPathForDisplay` creates visual alignment that aids in parsing the output structure.

The application relies on Spectre.Console's built-in accessibility features, which automatically adapt to terminal capabilities and can be configured through environment variables (though no explicit configuration is implemented in the current codebase).

## Customization Options

The application provides several customization options for controlling output verbosity and suppression through command-line parameters.

The primary customization option is the `showTable` parameter available in all commands (`verify`, `create`, `add`). When set to true, this parameter forces the diagnostic table to be displayed even when there are no issues, providing more detailed output for debugging or verification purposes.

Additional output control is achieved through:
- `tsvReport` parameter: Writes a machine-readable TSV error report to the specified path
- `include` and `exclude` parameters: Control which files are processed, indirectly affecting output volume
- `vss` parameter: Enables Volume Shadow Copy Service mode for accessing locked files (requires elevation)

The `CliOptions` record encapsulates these options, providing a clean interface between the command-line arguments and the rest of the application. The options are passed through to the presentation layer, allowing conditional rendering of components based on user preferences.

The application follows a principle of minimal output by default, showing detailed diagnostic information only when problems are detected or when explicitly requested. This prevents information overload during successful operations while still providing comprehensive details when needed.

```
csharp
public record struct CliOptions(
    FileInfo ChecksumFile,
    DirectoryInfo? RootDirectory,
    string Algorithm,
    FileInfo? TsvReportFile = null,
    bool ShowTable = false,
    string[]? IncludeGlobs = null,
    string[]? ExcludeGlobs = null,
    bool UseVss = false
);

```

## VSS Mode Header Display

The terminal UI now includes a dedicated display for Volume Shadow Copy Service (VSS) mode when enabled. This feature enhances transparency by clearly indicating when the application is operating in VSS snapshot mode, which is essential for accessing locked system files.

The VSS mode indicator is implemented in the `Utilities.BuildHeaderPanel()` method, which conditionally adds a "Mode" field to the header panel when the `UseVss` option is enabled. The header panel displays "VSS Snapshot Mode" as the mode value, providing immediate visual feedback to users.

The implementation follows a clean pattern of conditional content addition:
```
csharp
if (!string.IsNullOrEmpty(vssMode))
  content += $"[bold]Mode:[/] {vssMode}\n";
```

When VSS mode is requested via the `--vss` command line flag, the application first checks elevation status using `ElevationHelper.IsElevated()`. If not elevated, it prompts for elevation before proceeding. Once elevated, the `UseVss` flag is passed through the `CliOptions` to the header panel construction.

The VSS mode workflow includes:
1. Command line detection of `--vss` flag
2. Elevation check and request if needed
3. VSS snapshot creation using `VssSnapshotManager`
4. Header panel display with "VSS Snapshot Mode" indicator
5. File processing through snapshot paths resolved by `VssPathResolver`
6. Automatic cleanup of VSS snapshot on completion

This enhancement improves user experience by making the privileged operation mode explicit in the UI, helping users understand why elevation was requested and confirming that VSS mode is active.
