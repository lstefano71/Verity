## Output Stream Separation

Verity implements a clear separation between human-readable console output and machine-readable reports using standard I/O streams. The application uses stdout for interactive terminal UI elements and stderr for machine-parsable TSV reports, enabling clean integration in automated environments.

The `ResultsPresenter.WriteErrorReportAsync` method in ResultsPresenter.cs controls this behavior, writing TSV reports to stderr when no output file is specified:


```csharp
public static async Task WriteErrorReportAsync(FinalSummary summary, FileInfo? outputFile = null)
{
    var errorReport = new StringBuilder();
    errorReport.AppendLine("#Status\tFile\tDetails\tExpectedHash\tActualHash");

    foreach (var result in summary.ProblematicResults.OrderBy(r => r.Status).ThenBy(r => r.Entry.RelativePath)) {
        errorReport.AppendLine(string.Join("\t",
            result.Status.ToString().ToUpperInvariant(),
            result.FullPath ?? result.Entry.RelativePath,
            result.Details ?? "",
            result.Entry.ExpectedHash,
            result.ActualHash ?? ""
        ));
    }

    if (outputFile != null) {
        await File.WriteAllTextAsync(outputFile.FullName, errorReport.ToString());
    }
    // Only write to stderr if no output file specified
    else {
        await global::System.Console.Error.WriteAsync(errorReport.ToString());
    }
}
```


This design ensures that:
- Human-readable output (progress bars, summary tables) goes to stdout
- Machine-readable TSV reports go to stderr when no `--tsv-report` file is specified
- When `--tsv-report` is used, TSV output goes to the specified file and stderr remains clean

## Command-Line Patterns for Output Redirection

Verity supports several command-line patterns for redirecting output in automated environments. The `--tsv-report` option allows directing machine-readable output to files while preserving terminal feedback.

### Basic Redirection Patterns

Redirect TSV output to file while showing human-readable output in terminal:

```bash
Verity.exe verify manifest.sha256 --tsv-report errors.tsv
```


Process TSV output directly from stderr in a pipeline:

```bash
Verity.exe verify manifest.sha256 2>&1 | grep "ERROR"
```


Capture both streams separately in PowerShell:

```powershell
Verity.exe verify manifest.sha256 --tsv-report errors.tsv > console.log 2> errors.log
```


Suppress human-readable output and capture only TSV errors:

```bash
Verity.exe verify manifest.sha256 1> NUL
```


### Advanced Redirection with Filtering

Process only error-level issues from TSV output:

```bash
Verity.exe verify manifest.sha256 2>&1 | awk -F'\t' '$1 == "ERROR"'
```


Count the number of failed files directly from stderr:

```bash
Verity.exe verify manifest.sha256 2>&1 | grep "^ERROR" | wc -l
```

## Exit Code Handling in Automation Scripts

Verity uses distinct exit codes to communicate execution status to calling scripts, enabling automated decision-making in CI/CD pipelines and scheduled tasks.

### Exit Code Semantics

| Exit Code | Meaning | Automation Response |
|-----------|-------|-------------------|
| `0` | Success (no warnings or errors) | Proceed with next steps |
| `1` | Warning (warnings present, no errors) | Log warning, continue pipeline |
| `-1` | Error (verification errors found) | Fail pipeline, trigger alerts |
| `-2` | Canceled by user | Handle interruption gracefully |

The exit code logic is implemented in Program.cs across the main command methods:


```csharp
if (summary.ErrorCount > 0) return -1;
if (summary.WarningCount > 0) return 1;
return 0;
```


### PowerShell Script Example


```powershell
# Verify backup integrity and respond to exit codes
$verityPath = "Verity.exe"
$manifestPath = "backup-manifest.sha256"

& $verityPath verify $manifestPath --tsv-report "verification-results.tsv"

switch ($LASTEXITCODE) {
    0 {
        Write-Host "Verification successful: No issues found"
        # Continue with archive process
        Exit 0
    }
    1 {
        Write-Warning "Verification completed with warnings"
        # Parse TSV to determine warning severity
        $warnings = Import-Csv "verification-results.tsv" -Delimiter "`t"
        $fileNotFoundCount = ($warnings | Where-Object { $_.Details -eq "File not found" }).Count
        
        if ($fileNotFoundCount -gt 10) {
            Write-Error "Too many missing files: $fileNotFoundCount"
            Exit 1
        }
        # Proceed with caution
        Exit 0
    }
    -1 {
        Write-Error "Verification failed: Critical errors detected"
        # Send alert
        Send-Alert "Backup verification failed" -Severity Critical
        Exit 1
    }
    -2 {
        Write-Warning "Verification was canceled"
        Exit 2
    }
    default {
        Write-Error "Unknown exit code: $LASTEXITCODE"
        Exit 1
    }
}
```


### Bash Script Example


```bash
#!/bin/bash
set -euo pipefail

VERITY="./Verity.exe"
MANIFEST="backup-manifest.sha256"
TSV_REPORT="results.tsv"

# Execute verification with TSV output
"$VERITY" verify "$MANIFEST" --tsv-report "$TSV_REPORT"

EXIT_CODE=$?

case $EXIT_CODE in
    0)
        echo "SUCCESS: Backup verification passed"
        exit 0
        ;;
    1)
        echo "WARNING: Backup verification completed with warnings"
        # Count specific warning types
        HASH_MISMATCH_COUNT=$(grep "^ERROR" "$TSV_REPORT" | wc -l)
        if [ $HASH_MISMATCH_COUNT -gt 0 ]; then
            echo "Error: $HASH_MISMATCH_COUNT files have hash mismatches"
            exit 1
        fi
        # Proceed with non-critical warnings
        exit 0
        ;;
    -1)
        echo "ERROR: Backup verification failed"
        # Extract critical failures for alerting
        CRITICAL_ERRORS=$(grep "^ERROR" "$TSV_REPORT" | head -5)
        echo "Critical failures:"
        echo "$CRITICAL_ERRORS"
        exit 1
        ;;
    -2)
        echo "INFO: Verification was canceled by user"
        exit 2
        ;;
    *)
        echo "ERROR: Unknown exit code $EXIT_CODE"
        exit 1
        ;;
esac
```

## TSV Report Processing Examples

The TSV report format provides a standardized machine-readable output for automation scripts to parse and act upon verification results.

### TSV Report Structure

The TSV report follows a consistent format with a header row (prefixed with #) and data rows:


```
#Status	File	Details	ExpectedHash	ActualHash
ERROR	data/file1.txt	Hash mismatch	820208145359d1c620d459f00784e190	9d8f7g6h5j4k3l2m1n0o9p8q7r6s5t4u
WARNING	data/file2.txt	File is newer than manifest	375d554729e87a93f65cd724bbd29d96	375d554729e87a93f65cd724bbd29d96
ERROR	data/file3.txt	File not found		
```


### TSV Parsing Implementation

The test suite includes a TsvReportParser that demonstrates how to process these reports:


```csharp
public record TsvReportRow(string Status, string File, string Details, string ExpectedHash, string ActualHash);

public static class TsvReportParser
{
    public static List<TsvReportRow> Parse(string tsvContent)
    {
        var rows = new List<TsvReportRow>();
        var lines = tsvContent.Split(['\r', '\n'], StringSplitOptions.RemoveEmptyEntries);
        var dataLines = lines.Where(l => !l.StartsWith('#'));
        foreach (var line in dataLines) {
            var parts = line.Split('\t');
            if (parts.Length == 5) {
                rows.Add(new TsvReportRow(
                    Status: parts[0],
                    File: parts[1],
                    Details: parts[2],
                    ExpectedHash: parts[3],
                    ActualHash: parts[4]
                ));
            }
        }
        return rows;
    }
}
```

## CI/CD Pipeline Integration Best Practices

Integrating Verity into CI/CD pipelines requires careful consideration of output handling, error detection, and reporting.

### Pipeline Configuration Examples

#### GitHub Actions


```yaml
name: Backup Verification

  schedule:
    - cron: '0 2 * * *'  # Run nightly at 2 AM

jobs:
  verify-backup:
    runs-on: windows-latest
    steps:
    - name: Checkout repository
      uses: actions/checkout@v4
      
    - name: Setup .NET
      uses: actions/setup-dotnet@v3
      with:
        dotnet-version: '9.0.x'

      id: verify

      if: ${{ steps.verify.outputs.exit_code != 0 }}
```

### Logging and Monitoring Recommendations

1. **Structured Logging**: Capture both human-readable and machine-readable outputs
2. **Centralized Storage**: Store TSV reports in a durable location for audit purposes
3. **Alert Thresholds**: Define thresholds for different issue types (e.g., fail pipeline if >5 hash mismatches)
4. **Historical Analysis**: Maintain a history of verification results to detect trends
5. **Output Suppression**: In verbose pipeline environments, redirect human-readable output to reduce log noise

## Real-World Scenario: Nightly Backup Verification

This comprehensive example demonstrates how to implement a production-ready nightly backup verification system with email alerts.

### Complete PowerShell Script


```powershell
# NightlyBackupVerification.ps1
param(
    [string]$ManifestPath = "D:\backups\current\backup-manifest.sha256",
    [string]$ResultsPath = "D:\logs\verity-results.tsv",
    [string]$LogPath = "D:\logs\backup-verification.log",
    [string[]]$AlertEmails = @("admin@company.com"),
    [string]$SmtpServer = "smtp.company.com",
    [int]$MaxMissingFiles = 3,
    [int]$MaxHashMismatches = 0
)

$VerityPath = "D:\tools\Verity.exe"
$Timestamp = Get-Date -Format "yyyy-MM-dd HH:mm:ss"
$ScriptName = "Nightly Backup Verification"

# Initialize log
Add-Content -Path $LogPath -Value "[$Timestamp] Starting $ScriptName for $ManifestPath"

try {
    # Run verification with TSV output
    $process = Start-Process -FilePath $VerityPath `
        -ArgumentList "verify", $ManifestPath, "--tsv-report", $ResultsPath `
        -RedirectStandardOutput "$env:TEMP\verity-out.log" `
        -RedirectStandardError "$env:TEMP\verity-err.log" `
        -Wait -PassThru

    $ExitCode = $process.ExitCode
    Add-Content -Path $LogPath -Value "[$Timestamp] Verity exited with code: $ExitCode"

    # Always process results if TSV file was created
    if (Test-Path $ResultsPath) {
        $results = Import-Csv -Path $ResultsPath -Delimiter "`t"
        
        $summary = @{
            TotalErrors = ($results | Where-Object { $_.Status -eq "ERROR" }).Count
            TotalWarnings = ($results | Where-Object { $_.Status -eq "WARNING" }).Count
            HashMismatches = ($results | Where-Object { $_.Details -eq "Hash mismatch" }).Count
            MissingFiles = ($results | Where-Object { $_.Details -eq "File not found" }).Count
            NewerFiles = ($results | Where-Object { $_.Details -eq "File is newer than manifest" }).Count
        }
        
        Add-Content -Path $LogPath -Value "[$Timestamp] Analysis: Errors=$($summary.TotalErrors), Warnings=$($summary.TotalWarnings)"
    }
    else {
        Add-Content -Path $LogPath -Value "[$Timestamp] No TSV report generated"
        $summary = @{ TotalErrors = 0; TotalWarnings = 0; HashMismatches = 0; MissingFiles = 0; NewerFiles = 0 }
    }

    # Determine alert level
    $sendAlert = $false
    $alertSubject = ""
    $alertBody = ""

    switch ($ExitCode) {
        0 {
            $alertSubject = "SUCCESS: $ScriptName"
            $alertBody = "Backup verification completed successfully with no issues."
            $sendAlert = $false  # Only send success alerts if desired
        }
        1 {
            if ($summary.HashMismatches -gt $MaxHashMismatches -or $summary.MissingFiles -gt $MaxMissingFiles) {
                $sendAlert = $true
                $alertSubject = "FAILURE: $ScriptName"
                $alertBody = @"
Backup verification completed with critical warnings:

- Hash mismatches: $($summary.HashMismatches) (threshold: $MaxHashMismatches)
- Missing files: $($summary.MissingFiles) (threshold: $MaxMissingFiles)

See attached TSV report for details.
"@
            }
            else {
                $alertSubject = "WARNING: $ScriptName"
                $alertBody = "Backup verification completed with acceptable warnings."
                $sendAlert = $true
            }
        }
        -1 {
            $sendAlert = $true
            $alertSubject = "FAILURE: $ScriptName"
            $alertBody = @"
Critical errors detected during backup verification:

- Total errors: $($summary.TotalErrors)
- Hash mismatches: $($summary.HashMismatches)
- Missing files: $($summary.MissingFiles)

Immediate investigation required. See attached TSV report.
"@
        }
        default {
            $sendAlert = $true
            $alertSubject = "ERROR: $ScriptName"
            $alertBody = "Backup verification failed with unexpected exit code: $ExitCode"
        }
    }

    # Send email alert if needed
    if ($sendAlert) {
        try {
            $smtp = New-Object Net.Mail.SmtpClient($SmtpServer)
            $mail = New-Object Net.Mail.MailMessage
            $mail.From = "backup-monitor@company.com"
            $alertEmails | ForEach-Object { $mail.To.Add($_) }
            $mail.Subject = $alertSubject
            $mail.Body = $alertBody
            
            if (Test-Path $ResultsPath) {
                $attachment = New-Object Net.Mail.Attachment($ResultsPath)
                $mail.Attachments.Add($attachment)
            }
            
            $smtp.Send($mail)
            Add-Content -Path $LogPath -Value "[$Timestamp] Alert email sent: $alertSubject"
        }
        catch {
            Add-Content -Path $LogPath -Value "[$Timestamp] Failed to send alert email: $($_.Exception.Message)"
        }
    }

    # Clean up temporary files
    Remove-Item "$env:TEMP\verity-*.log" -ErrorAction SilentlyContinue

    # Exit with original exit code for pipeline integration
    exit $ExitCode
}
catch {
    $errorMessage = "[$Timestamp] Script failed: $($_.Exception.Message)"
    Add-Content -Path $LogPath -Value $errorMessage
    
    # Send critical failure alert
    try {
        $smtp = New-Object Net.Mail.SmtpClient($SmtpServer)
        $mail = New-Object Net.Mail.MailMessage
        $mail.From = "backup-monitor@company.com"
        $alertEmails | ForEach-Object { $mail.To.Add($_) }
        $mail.Subject = "CRITICAL: $ScriptName Failed to Execute"
        $mail.Body = "The backup verification script failed to execute: $($_.Exception.Message)`r`nCheck logs for details."
        $smtp.Send($mail)
    }
    catch {
        Add-Content -Path $LogPath -Value "[$Timestamp] Failed to send critical alert: $($_.Exception.Message)"
    }
    
    exit 1
}
```

## Buffering and Output Flushing Considerations

Proper output flushing is critical in headless environments to ensure complete output capture, especially when processes are terminated or when monitoring real-time output.

### Command Execution Lifecycle and Output Timing

The Program.cs file reveals the command execution lifecycle, which affects output timing and flushing:


```csharp
public static async Task Main(string[] args)
{
    // Check if VSS mode is requested
    bool vssRequested = args.Any(arg => string.Equals(arg, "--vss", StringComparison.OrdinalIgnoreCase) ||
                                        string.Equals(arg, "-vss", StringComparison.OrdinalIgnoreCase));

    // If VSS mode is requested and we're not elevated, try to restart with elevation
    if (vssRequested && !ElevationHelper.IsElevated())
    {
        AnsiConsole.MarkupLine("[yellow]VSS mode requires administrator privileges. Requesting elevation...[/]");
        
        try
        {
            bool restarted = await ElevationHelper.RestartElevatedAsync(args);
            if (restarted)
            {
                AnsiConsole.MarkupLine("[green]Restarting with elevated privileges...[/]");
                Environment.Exit(0); // Exit the original process
            }
            else
            {
                AnsiConsole.MarkupLine("[red]Elevation was declined. VSS mode cannot be used without administrator privileges.[/]");
                Environment.Exit((int)VssErrorCode.ElevationRequired);
            }
        }
        catch (Exception ex)
        {
            AnsiConsole.MarkupLine($"[red]Failed to restart with elevation: {ex.Message}[/]");
            Environment.Exit((int)VssErrorCode.ElevationRequired);
        }
    }

    var app = ConsoleApp.Create();
    app.Add<Program>();
    await app.RunAsync(args);
}
```


Key timing considerations:
1. **Pre-initialization output**: Messages before `app.RunAsync` are written immediately
2. **Command execution**: All command-specific output occurs within the command methods
3. **Finalization**: TSV reports and exit codes are generated at the end of command execution

### Ensuring Complete Output Flushing

In automated environments, especially when using process monitoring or timeouts, ensure complete output by:

1. **Explicit flushing**:

```csharp
// The ResultsPresenter already ensures complete output by awaiting WriteAsync
await global::System.Console.Error.WriteAsync(errorReport.ToString());
// The async method ensures the write operation completes
```


2. **PowerShell best practices**:

```powershell
# Use Start-Process with -Wait to ensure complete execution
$result = Start-Process -FilePath "Verity.exe" -ArgumentList "verify manifest.sha256" -Wait -PassThru

# Check exit code and output
if ($result.ExitCode -ne 0) {
    # Process error output
    $tsvContent = Get-Content "results.tsv" -Raw
}
```


3. **Bash best practices**:

```bash
#!/bin/bash
set -euo pipefail

# Use wait to ensure process completion
./Verity.exe verify manifest.sha256 --tsv-report results.tsv
EXIT_CODE=$?

# Verify TSV file exists and has content before proceeding
if [ $EXIT_CODE -ne 0 ] && [ -s "results.tsv" ]; then
    # Process results
    grep "^ERROR" results.tsv
fi
```


4. **Handling timeouts with graceful termination**:

```powershell
# Use a job to allow for graceful termination
$job = Start-Job { & "Verity.exe" verify "manifest.sha256" --tsv-report "results.tsv" }

# Wait with timeout
if (Wait-Job $job -Timeout 3600) {
    $result = Receive-Job $job
    $exitCode = $job.State -eq 'Completed' ? 0 : 1
} else {
    # Graceful termination allows final output to be written
    Stop-Job $job
    $result = Receive-Job $job
    $exitCode = 2
    Add-Content "verification.log" "Job terminated due to timeout"
}

Remove-Job $job
```


### Headless Environment Considerations

When running in CI/CD agents or scheduled tasks:
