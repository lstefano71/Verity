## VSS Error Codes
The Verity application defines a specific enumeration for VSS-related error codes, each with a unique numeric value and semantic meaning. These error codes are used as exit codes when VSS operations fail, allowing external systems to programmatically respond to different failure scenarios.


```csharp
public enum VssErrorCode
{
    ElevationRequired = 100,
    VssNotAvailable = 101,
    SnapshotCreationFailed = 102,
    VolumeNotSupported = 103
}
```


### Error Code Reference
**VssErrorCode.ElevationRequired (100)**
- **Meaning**: The current operation requires administrator privileges to access VSS functionality.
- **Trigger Conditions**: Attempting to use VSS features without sufficient privileges.
- **Resolution**: Run the application with elevated administrator privileges.

**VssErrorCode.VssNotAvailable (101)**
- **Meaning**: The VSS service is not available on the current system.
- **Trigger Conditions**: VSS components cannot be loaded or initialized.
- **Resolution**: Ensure Windows Volume Shadow Copy Service is running and available.

**VssErrorCode.SnapshotCreationFailed (102)**
- **Meaning**: Failed to create a VSS snapshot despite having proper privileges.
- **Trigger Conditions**: Timeout during snapshot creation, VSS API failures, or internal errors.
- **Resolution**: Check system resources, VSS service status, and retry the operation.

**VssErrorCode.VolumeNotSupported (103)**
- **Meaning**: The specified volume does not support VSS snapshots.
- **Trigger Conditions**: Attempting to snapshot a volume that lacks VSS provider support.
- **Resolution**: Verify the volume type and ensure it supports shadow copies.

## Elevation Requirement Handling
The application implements a proactive elevation handling strategy that detects privilege requirements and guides users through the elevation process.

### Elevation Detection and Restart
When VSS mode is requested via command-line arguments, the application checks the current privilege level and initiates an elevation restart if necessary:

``mermaid

App->>App : Check IsElevated()

App->>App : Display elevation prompt
App->>OS : Request elevation (runas)
alt User Accepts
OS->>App : Launch elevated instance
App->>User : Continue with VSS operations
else User Declines
OS->>App : Cancel elevation

end
else Already Elevated
App->>User : Proceed with VSS operations
end
```

### Implementation Details
The elevation handling is implemented in two key components:

1. **Program.cs**: Entry point logic that checks for VSS flag and elevation status
2. **ElevationHelper.cs**: Utility class with methods for privilege detection and elevation restart


```csharp
// In Program.cs
if (vssRequested && !ElevationHelper.IsElevated())
{
    AnsiConsole.MarkupLine("[yellow]VSS mode requires administrator privileges. Requesting elevation...[/]");
    
    try
    {
        bool restarted = await ElevationHelper.RestartElevatedAsync(args);
        if (restarted)
        {
            Environment.Exit(0); // Exit original process
        }
        else
        {
            Environment.Exit((int)VssErrorCode.ElevationRequired);
        }
    }
    catch (Exception ex)
    {
        Environment.Exit((int)VssErrorCode.ElevationRequired);
    }
}
```

### Failure Types and Handling
**Timeout Failures**
- Occur when snapshot creation exceeds the configured timeout (default: 5 minutes)
- Handled by `CancellationTokenSource` with timeout
- Result in `VssSnapshotException` with timeout message
- Exit code: `SnapshotCreationFailed (102)`

**VSS API Failures**
- Occur when any VSS API call fails (InitializeForBackup, AddToSnapshotSet, etc.)
- Caught and wrapped in `VssSnapshotException`
- Automatic cleanup via `CleanupSnapshot()`
- Exit code: `SnapshotCreationFailed (102)`

**Invalid Snapshot Path**
- Occurs when VSS returns empty or null device object path
- Explicit validation after `GetSnapshotProperties()`
- Thrown as `VssSnapshotException`
- Exit code: `SnapshotCreationFailed (102)`

## Volume Support Validation
The system validates volume compatibility with VSS before attempting snapshot creation, though this validation is primarily implicit through the VSS API calls.

### Volume Compatibility Requirements
For a volume to support VSS snapshots, it must:
- Be a local NTFS volume (typically)
- Have the VSS writer service running
- Not be in a state that prevents shadow copies
- Have sufficient disk space for shadow storage

### Error Code Mapping
When a volume does not support VSS snapshots, the error is typically detected during the `AddToSnapshotSet` or `DoSnapshotSet` calls, resulting in:

```
csharp
return (int)VssErrorCode.VolumeNotSupported;

```

This occurs in the main program flow when VSS operations fail due to volume incompatibility.

### Key Features
- **Automatic Cleanup on Failure**: `CleanupSnapshot()` called in catch blocks when snapshot creation fails
- **Dispose Pattern**: Implements `IDisposable` for deterministic cleanup
- **Finalizer**: Backup cleanup in case `Dispose()` is not called
- **Error Tolerance**: Cleanup errors are logged but not propagated

The `Dispose()` method ensures that resources are properly released:


```csharp
public void Dispose()
{
    if (!_disposed)
    {
        CleanupSnapshot();
        _disposed = true;
    }
    GC.SuppressFinalize(this);
}
```

## Troubleshooting Guide
This section provides practical guidance for diagnosing and resolving common VSS error scenarios.

### Elevation Required (100)
**Symptoms**:
- Application exits immediately with code 100
- Message: "Elevation was declined. VSS mode cannot be used without administrator privileges."

**Solutions**:
1. Right-click the application and select "Run as administrator"
2. Use command prompt with administrator privileges
3. Configure application compatibility settings for administrator mode

**Prevention**:
- Always run the application with administrator privileges when using VSS features
- Consider application manifest with `requireAdministrator` level

### Snapshot Creation Failed (102)
**Common Causes**:
- VSS service not running
- Insufficient disk space for shadow copies
- Volume in use by other processes
- Antivirus software interference
- Timeout due to system load

**Diagnostic Steps**:
1. Check Windows Event Viewer for VSS-related errors
2. Verify Volume Shadow Copy service is running
3. Check available disk space on the system volume
4. Run `vssadmin list writers` to check VSS writer status
5. Temporarily disable antivirus software

**Resolution**:
- Restart the Volume Shadow Copy service
- Free up disk space
- Retry the operation during low system usage
- Increase the snapshot timeout if appropriate

### Volume Not Supported (103)
**Common Causes**:
- Non-NTFS volumes (FAT32, exFAT)
- Network drives or mapped drives
- Removable media
- System volumes with corrupted VSS metadata

**Verification**:

```cmd
vssadmin list volumes
```


This command shows which volumes support shadow copies.

**Solutions**:
- Use only NTFS-formatted local volumes
- Convert volume to NTFS if possible
- Check VSS service status and restart if needed
- Run `vssadmin repair` to fix VSS metadata

### General Best Practices
- Always run VSS operations with administrator privileges
- Monitor available disk space for shadow storage
- Implement retry logic for transient failures
- Use appropriate timeout values based on system performance
- Clean up snapshots promptly to avoid resource leaks
