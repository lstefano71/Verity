## VSS Error Codes
The Verity application defines a specific enumeration for VSS-related error codes, each with a unique numeric value and semantic meaning. These error codes are used as exit codes when VSS operations fail, allowing external systems to programmatically respond to different failure scenarios.


```csharp
public enum VssErrorCode
{
    ElevationRequired = 100,
    VssNotAvailable = 101,
    SnapshotCreationFailed = 102,
    VolumeNotSupported = 103
}
```


### Error Code Reference
**VssErrorCode.ElevationRequired (100)**
- **Meaning**: The current operation requires administrator privileges to access VSS functionality.
- **Trigger Conditions**: `--vss` was used without administrator rights and the UAC prompt was declined (`ElevationOutcome.Declined`), or the elevated relaunch could not be started (`ElevationOutcome.Failed`). If the relaunch succeeds, the original process instead exits with the elevated child's exit code.
- **Resolution**: Accept the UAC prompt, or run the application from an elevated prompt.

**VssErrorCode.VssNotAvailable (101)**
- **Meaning**: The VSS service is not available on the current system.
- **Trigger Conditions**: Reserved; the current code does not return this code (failures to load or initialize VSS components surface as `SnapshotCreationFailed` (102)).
- **Resolution**: Ensure Windows Volume Shadow Copy Service is running and available.

**VssErrorCode.SnapshotCreationFailed (102)**
- **Meaning**: Failed to create a VSS snapshot despite having proper privileges.
- **Trigger Conditions**: Timeout during snapshot creation (`VssSnapshotException` "timed out"), VSS API failures (including running without elevation), or internal errors. A user cancel (Ctrl+C) during creation is not reported as 102: it propagates as `OperationCanceledException` and the command exits with `-2` (Interrupted).
- **Resolution**: Check system resources, VSS service status, and retry the operation.

**VssErrorCode.VolumeNotSupported (103)**
- **Meaning**: The specified volume does not support VSS snapshots.
- **Trigger Conditions**: Returned by the `VssSetup` phase when the volume root of the root directory cannot be determined (`Path.GetPathRoot` is empty). A volume whose VSS provider rejects the snapshot fails inside snapshot creation and is reported as `SnapshotCreationFailed` (102).
- **Resolution**: Verify the volume type and ensure it supports shadow copies.

## Elevation Requirement Handling
The application implements a proactive elevation handling strategy that detects privilege requirements and guides users through the elevation process.

### Elevation Detection and Restart
When VSS mode is requested via command-line arguments, the application checks the current privilege level and, if necessary, relaunches the command elevated in its own console window. The original process waits for the elevated child and exits with the child's exit code, so scripts see the real result:

``mermaid
sequenceDiagram
participant User
participant App as "Application"
participant OS as "Operating System"
User->>App : Execute with --vss flag
App->>App : Check IsElevated()
alt Not Elevated
App->>App : Display elevation prompt
App->>OS : Request elevation (runas)
alt User Accepts
OS->>App : Launch elevated child (new window, --verity-elevated-child)
App->>App : Wait for child to exit
App->>User : Exit with the child's exit code
else User Declines (ERROR_CANCELLED 1223) or start fails
OS->>App : Cancel elevation / error
App->>User : Exit with ElevationRequired (100)
end
else Already Elevated
App->>User : Proceed with VSS operations
end
```

### Implementation Details
The elevation handling is implemented in two key components:

1. **Program.cs**: Entry point logic that checks for VSS flag and elevation status
2. **ElevationHelper.cs**: Utility class with methods for privilege detection and elevation relaunch. `EnsureElevatedAsync` returns an `ElevationOutcome` (NotRequired, AlreadyElevated, Relaunched, Declined, Failed); `RestartElevatedAsync` returns `Task<int?>`, the child's exit code or `null` if UAC was declined, and throws for other start failures


```csharp
// In Program.Main (the elevated child carries --verity-elevated-child, stripped before parsing)
bool elevationRequired = vssRequested && !isElevatedChild;
if (elevationRequired && !ElevationHelper.IsElevated())
    AnsiConsole.MarkupLine("[yellow]VSS mode requires administrator privileges. Requesting elevation; the run continues in a new window...[/]");

var elevation = await ElevationHelper.EnsureElevatedAsync(args, elevationRequired);
switch (elevation.Outcome)
{
    case ElevationOutcome.Relaunched:
        AnsiConsole.MarkupLine($"Elevated run finished with exit code {elevation.ExitCode}.");
        Environment.Exit(elevation.ExitCode!.Value); // propagate the real result to scripts
        return;
    case ElevationOutcome.Declined:
        AnsiConsole.MarkupLine("[red]Elevation was declined. VSS mode cannot be used without administrator privileges.[/]");
        Environment.Exit((int)VssErrorCode.ElevationRequired);
        return;
    case ElevationOutcome.Failed:
        AnsiConsole.MarkupLine($"[red]Failed to restart with elevation: {Markup.Escape(elevation.Error!.Message)}[/]");
        Environment.Exit((int)VssErrorCode.ElevationRequired);
        return;
}
// NotRequired / AlreadyElevated: continue in this process
```

### Failure Types and Handling
**Timeout Failures**
- Occur when snapshot creation exceeds the configured timeout (default: 5 minutes)
- Handled by a timeout `CancellationTokenSource` linked with the caller's token; `PrepareForBackup` and `DoSnapshotSet` use the asynchronous AlphaVSS calls with that token, so the timeout actually interrupts them
- Result in `VssSnapshotException` with a "timed out" message
- Exit code: `SnapshotCreationFailed (102)`

**User Cancellation (Ctrl+C)**
- The caller's token interrupts the same asynchronous calls
- The creation is rolled back and `OperationCanceledException` propagates (not wrapped)
- Exit code: `Interrupted (-2)`

**VSS API Failures**
- Occur when any VSS API call fails (InitializeForBackup, AddToSnapshotSet, etc.)
- Caught and wrapped in `VssSnapshotException`
- Automatic rollback via `CleanupSnapshot()`; the manager returns to `New`
- Exit code: `SnapshotCreationFailed (102)`

**Invalid Snapshot Path**
- Occurs when VSS returns empty or null device object path
- Explicit validation after `GetSnapshotProperties()`
- Thrown as `VssSnapshotException`
- Exit code: `SnapshotCreationFailed (102)`

## Volume Support Validation
The system validates volume compatibility with VSS before attempting snapshot creation, though this validation is primarily implicit through the VSS API calls.

### Volume Compatibility Requirements
For a volume to support VSS snapshots, it must:
- Be a local NTFS volume (typically)
- Have the VSS writer service running
- Not be in a state that prevents shadow copies
- Have sufficient disk space for shadow storage

### Error Code Mapping
When a volume does not support VSS snapshots, the error is typically detected during the `AddToSnapshotSet` or `DoSnapshotSet` calls; it surfaces as a `VssSnapshotException` and the command exits with `SnapshotCreationFailed (102)`. `VolumeNotSupported (103)` is returned only by `RunPipeline.VssSetupAsync` when the volume root cannot be determined:

```csharp
var volumeRoot = Path.GetPathRoot(run.RootPath);
if (string.IsNullOrEmpty(volumeRoot)) {
  AnsiConsole.MarkupLine("[red]Error: Unable to determine volume root for VSS snapshot.[/]");
  return Exit(run, (int)VssErrorCode.VolumeNotSupported);
}
```

## Resource Cleanup and Disposal
The VSS system implements proper resource management to ensure snapshots are cleaned up even in failure scenarios.

### Cleanup Mechanism
``mermaid
flowchart TD

B --> |Yes| S{"Last completed step?"}
S --> |"SnapshotTaken or later"| C["DeleteSnapshotSet()"]
S --> |"SnapshotSetStarted .. Prepared"| C2["AbortBackup()"]
S --> |Earlier| F
C2 --> D
C --> D{"Success?"}
D --> |No| E["Write warning to stderr"]
D --> |Yes| F["Continue Cleanup"]
E --> F
F --> G["Dispose Backup Components"]
G --> H["Reset State Variables"]
H --> End["Cleanup Complete"]
B --> |No| H
```


**Diagram sources**
- [VssSnapshotManager.cs](file://Verity/Utilities/VssSnapshotManager.cs#L148-L193)

### Key Features
- **Explicit lifecycle**: `VssSnapshotState` (New, Creating, Active, Disposed); `VssCreationStep` records the last completed protocol step so cleanup knows what to undo
- **Automatic Rollback on Failure**: `CleanupSnapshot()` is called from the single catch block when snapshot creation fails, times out or is cancelled: `AbortBackup` if the snapshot set was started but not committed, `DeleteSnapshotSet` once committed; the manager then returns to `New`
- **Pipeline cleanup**: `RunPipeline.RunAsync` disposes the manager in a `finally` block whichever way the run leaves
- **Dispose Pattern**: Implements `IDisposable` for deterministic cleanup
- **Finalizer**: Backup cleanup in case `Dispose()` is not called
- **Error Tolerance**: Cleanup errors are written as warnings to stderr (keeping redirected stdout clean) but not propagated

The `Dispose()` method ensures that resources are properly released:


```csharp
public void Dispose()
{
    lock (_gate)
    {
        if (_state == VssSnapshotState.Disposed)
            return;
        _state = VssSnapshotState.Disposed;
    }

    CleanupSnapshot();
    GC.SuppressFinalize(this);
}
```

## Troubleshooting Guide
This section provides practical guidance for diagnosing and resolving common VSS error scenarios.

### Elevation Required (100)
**Symptoms**:
- Application exits immediately with code 100
- Message: "Elevation was declined. VSS mode cannot be used without administrator privileges." or "Failed to restart with elevation: ..."

**Solutions**:
1. Right-click the application and select "Run as administrator"
2. Use command prompt with administrator privileges
3. Configure application compatibility settings for administrator mode

**Prevention**:
- Always run the application with administrator privileges when using VSS features
- Consider application manifest with `requireAdministrator` level

### Snapshot Creation Failed (102)
**Common Causes**:
- VSS service not running
- Insufficient disk space for shadow copies
- Volume in use by other processes
- Antivirus software interference
- Timeout due to system load

**Diagnostic Steps**:
1. Check Windows Event Viewer for VSS-related errors
2. Verify Volume Shadow Copy service is running
3. Check available disk space on the system volume
4. Run `vssadmin list writers` to check VSS writer status
5. Temporarily disable antivirus software

**Resolution**:
- Restart the Volume Shadow Copy service
- Free up disk space
- Retry the operation during low system usage
- Increase the snapshot timeout if appropriate

### Volume Not Supported (103)
**Common Causes**:
- Non-NTFS volumes (FAT32, exFAT)
- Network drives or mapped drives
- Removable media
- System volumes with corrupted VSS metadata

**Verification**:

```cmd
vssadmin list volumes
```


This command shows which volumes support shadow copies.

**Solutions**:
- Use only NTFS-formatted local volumes
- Convert volume to NTFS if possible
- Check VSS service status and restart if needed
- Run `vssadmin repair` to fix VSS metadata

### General Best Practices
- Always run VSS operations with administrator privileges
- Monitor available disk space for shadow storage
- Implement retry logic for transient failures
- Use appropriate timeout values based on system performance
- Clean up snapshots promptly to avoid resource leaks
