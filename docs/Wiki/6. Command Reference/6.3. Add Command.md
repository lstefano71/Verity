## Introduction
The `add` command in Verity is designed to update an existing manifest file by scanning a directory for new files that are not already listed in the manifest and appending their checksums. This functionality enables incremental updates to integrity manifests without modifying existing entries, preserving the immutability principle of the original manifest. The command supports flexible filtering via glob patterns, parallel processing, detailed reporting, and Volume Shadow Copy Service (VSS) integration for accessing locked files, making it suitable for automation in backup systems and CI/CD pipelines.

## Command Functionality
The `add` command performs an incremental update of a checksum manifest by identifying new files in a specified directory (or the manifest's directory by default), computing their cryptographic hashes, and appending the new entries to the manifest. The original manifest content remains unaltered, and only new files—those not already present in the manifest—are added. This ensures the integrity and immutability of the original manifest while allowing for scalable, ongoing file tracking.

The command infers the hashing algorithm (e.g., SHA256, MD5) from the manifest file extension unless explicitly overridden via the `--algorithm` option. It operates in a thread-safe manner using a lock in `ManifestWriter` to prevent race conditions during file writing. When the `--vss` flag is used, the command creates a Volume Shadow Copy snapshot to access files that may be locked by other processes, requiring administrator privileges.

## Required and Optional Arguments
The `add` command accepts several arguments to control its behavior:

**:Required Arguments**
- `manifestPath`: The path to the existing manifest file to be updated. This is a positional argument and must be provided.

**:Optional Arguments**
- `--root <directory>`: Specifies the root directory to scan for new files. Defaults to the directory containing the manifest.
- `--algorithm <name>`: Specifies the hashing algorithm (SHA256, MD5, SHA1). If omitted, the algorithm is inferred from the manifest file extension (e.g., `.sha256`, `.md5`).
- `--threads <number>`: Sets the number of parallel threads for file processing. Defaults to the number of processor cores.
- `--include <patterns>`: Semicolon-separated glob patterns to include files (e.g., `*.log;*.txt`). Defaults to all files.
- `--exclude <patterns>`: Semicolon-separated glob patterns to exclude files (e.g., `*.tmp;*.bak`). Takes precedence over `--include`.
- `--show-table`: Forces the diagnostic table to be displayed even if no issues are found.
- `--tsv-report <file>`: Writes a machine-readable TSV report of any warnings or errors to the specified file.
- `--vss`: Creates a Volume Shadow Copy Service (VSS) snapshot to access locked files. Requires administrator privileges and is supported only on Windows volumes with VSS capability.

## Manifest Reading and Writing Process
The `add` command uses `ManifestReader` to load the existing manifest entries and `ManifestWriter` to append new entries.

**:ManifestReader**
- Reads the manifest file line by line using `File.ReadLinesAsync`.
- Parses each line into a `ManifestEntry` containing a hash and relative path.
- Returns a list of entries, skipping malformed or empty lines.
- Used in `NewFilesAsync` to determine which files are already listed.

**:ManifestWriter**
- Uses a `StreamWriter` with a 4KB buffer to write entries.
- Implements thread safety via a `Lock` object to synchronize write operations.
- Provides `WriteEntryAsync` for single entries and `WriteAllEntriesAsync` for bulk writes.
- In `AddToManifestAsync`, it writes all entries (existing + new) in a single operation after deduplication.

When VSS is enabled, the `ManifestCreationService` uses a `VssPathResolver` to translate file paths to their VSS snapshot equivalents before reading, ensuring locked files can be accessed.

## File Discovery and Filtering
The `add` command discovers new files by scanning the root directory and comparing file paths against those already in the manifest.

**:File Scanning**
- Uses `DirectoryInfo.EnumerateFileSystemInfos` for efficient enumeration.
- Computes relative paths using `Path.GetRelativePath`.
- Checks if a file is already listed using a `HashSet<string>` for O(1) lookups.

**:Glob Filtering**
- `GlobUtils.NormalizeGlobs` splits semicolon-separated patterns into arrays.
- `GlobUtils.IsMatch` uses a `Matcher` from the `System.Buffers` library to evaluate glob patterns.
- `--exclude` patterns take precedence over `--include`.
- Default `--include` is `**/*` (all files), default `--exclude` is empty.

## Conflict Resolution and Immutability
The `add` command adheres to the immutability principle by never modifying existing manifest entries. Instead, it appends new entries only for files not already present.

**:Duplicate Path Handling**
- Before adding a new file, the system checks if its relative path exists in the manifest.
- If a file with the same path exists, it is not added again, preventing duplicates.
- This ensures that the manifest remains a consistent, append-only record.

**:Integrity Preservation**
- The original manifest data is preserved exactly as-is.
- New entries are appended in sorted order by path to maintain consistency.
- The operation is atomic in the sense that the entire updated manifest is written at once.

## Performance and Threading
The `add` command is optimized for performance through parallel processing and efficient I/O.

**:Parallel Processing**
- Uses `Task.WhenAll` with `Partitioner.Create` to distribute files across threads.
- The number of threads is configurable via `--threads` or defaults to `Environment.ProcessorCount`.
- Each thread processes a partition of files independently.

**:I/O Optimization**
- `FileIOUtils.GetOptimalBufferSize` selects buffer size based on file size:
  - 4KB for files ≤ 64KB
  - 1MB for larger files
- Uses `FileStream` with `FileOptions.Asynchronous` for async I/O.
- Employs `ArrayPool<byte>` to reduce memory allocations.

## Practical Examples
The following examples demonstrate common use cases for the `add` command.

**:Adding Log Files**
```
bash
Verity.exe add C:\logs\manifest.sha256 --root C:\logs\app --include "*.log"

```
Scans the `C:\logs\app` directory for new `.log` files and adds them to the manifest.

**:Updating Software Packages**
```
bash
Verity.exe add D:\packages\manifest.md5 --root D:\packages --exclude "*.tmp"

```
Adds all new files except temporary files to the package manifest.

**:Incremental Backup with VSS**
```
bash
Verity.exe add C:\backup\manifest.sha256 --root C:\data --include "*.docx" --vss

```
Creates a VSS snapshot to access locked Office documents and adds them to the backup manifest. Requires administrator privileges.

**:High-Performance Processing**
```
bash
Verity.exe add /backup/manifest.sha256 --root /data --include "*.docx;*.xlsx" --threads 8

```
Adds new Office documents to a backup manifest using 8 threads for faster processing.

## Integration in CI/CD and Backup Systems
The `add` command is ideal for incremental updates in automated systems.

**:CI/CD Pipelines**
- After each build, new artifacts can be added to a manifest.
- The exit code indicates success (0), warning (1), or error (-1), enabling pipeline control.
- TSV reports can be parsed for automated issue tracking.

**:Backup Systems**
- Daily backups can use `add` to include new or modified files.
- Combined with `verify`, it ensures data integrity over time.
- The append-only nature allows for audit trails and versioning.
- VSS support enables backup of files currently in use by applications.

## Error Handling and Reporting
The `add` command provides detailed feedback through console output and structured reports.

**:Exit Codes**
- `0`: Success (new files added or no new files)
- `1`: Warning (no new files to add)
- `-1`: Error (e.g., file read error, I/O failure)
- `-2`: Interrupted by user
- `-3`: VSS operation failed (e.g., elevation required, snapshot timeout)

**:Reporting**
- `ResultsPresenter` renders a summary table with success, warning, and error counts.
- Diagnostic table shows details of problematic files.
- TSV report provides machine-readable output for automation.

## VSS Support and Elevation Requirements
The `add` command now supports Volume Shadow Copy Service (VSS) to access files that are locked by other processes, such as system files or files in use by applications.

**:VSS Operation**
- When `--vss` is specified, the command creates a VSS snapshot of the volume containing the root directory.
- The `VssSnapshotManager` handles snapshot creation and lifecycle management.
- The `VssPathResolver` translates file paths to their VSS snapshot equivalents.
- Snapshots are automatically cleaned up when the command completes.

**:Elevation Requirements**
- VSS operations require administrator privileges.
- If the command is run without elevation when `--vss` is specified, it will automatically request elevation via UAC.
- If elevation is declined, the command exits with error code `-3` (VssErrorCode.ElevationRequired).
- The `ElevationHelper` class manages the elevation restart process.

**:Error Handling**
- `VssSnapshotException`: Thrown when snapshot creation fails (e.g., timeout, unsupported volume).
- `InvalidOperationException`: Thrown when attempting to create multiple snapshots with the same manager.
- Exit codes provide clear indication of VSS-related failures.
