## Command-Line Arguments Overview

The Verity application provides three primary commands: `verify`, `create`, and `add`. Each command accepts a combination of positional and optional arguments to control checksum operations.

**Positional Arguments**
- `checksumFile` / `outputManifest` / `manifestPath`: The path to the manifest file (for `verify`, `add`) or the output manifest (for `create`). This is a required positional argument.

**Optional Parameters**
- `root`: Specifies the root directory for resolving file paths. If not provided, defaults to the manifest file's directory.
- `algorithm`: The hashing algorithm to use (e.g., SHA256, MD5). If omitted, inferred from the manifest file extension (.sha256, .md5, .sha1).
- `threads`: Number of parallel threads to use. Defaults to the number of processor cores.
- `tsvReport`: Path to write a machine-readable TSV error report.
- `showTable`: Forces the diagnostic table to be shown even if there are no issues.
- `include`: Semicolon-separated glob patterns for files to include.
- `exclude`: Semicolon-separated glob patterns for files to exclude.
- `vss`: Creates a Volume Shadow Copy Service (VSS) snapshot for accessing locked files. Requires administrator privileges.

## Argument Parsing and Validation

Command-line arguments are parsed and validated through the ConsoleAppFramework library, which maps CLI inputs to method parameters in the `Program` class. The parsed arguments are then transformed into a `CliOptions` record for consistent handling across services.

``mermaid
flowchart TD
A["CLI Arguments"] --> B["Method Parameters in Program.cs"]
B --> C["Validation and Normalization"]
C --> D["CliOptions Record Creation"]
D --> E["Service Invocation"]

```

**Argument Binding Process**
1. The `Main` method initializes the ConsoleAppFramework application and registers the `Program` class.
2. When a command is invoked (e.g., `verify`, `create`, `add`), the framework binds CLI arguments to the corresponding method parameters.
3. The `CliOptions` record is constructed with validated inputs:
   - File paths are converted to `FileInfo` objects
   - Directory paths are converted to `DirectoryInfo` objects
   - Glob patterns are normalized using `GlobUtils.NormalizeGlobs`
   - Hashing algorithm is inferred from file extension if not specified
   - VSS flag is set based on the presence of `--vss` argument

**Validation Logic**
- Required positional arguments are enforced by the framework
- File and directory existence is not validated upfront but handled during execution
- Algorithm inference uses a simple extension-based mapping:
  - `.sha256` → SHA256
  - `.md5` → MD5  
  - `.sha1` → SHA1
  - Any other extension → SHA256 (default)

## Path Resolution and Cross-Platform Compatibility

Path resolution in Verity is designed to be cross-platform compatible, handling both Windows and Unix-style path separators correctly.

**Root Directory Semantics**
- The `--root` parameter explicitly sets the base directory for relative path resolution
- When `--root` is not specified, the manifest file's directory is used as the default root
- All file paths in the manifest are interpreted relative to this root directory

**Path Normalization**
- All paths are normalized to use the platform's directory separator (`\` on Windows, `/` on Unix)
- Relative paths are calculated using `Path.GetRelativePath()`
- Symbolic links are resolved to their target paths during file enumeration

**Cross-Platform Considerations**
- Case sensitivity: File matching is case-insensitive on Windows, case-sensitive on Unix
- Path separator: Both `/` and `\` are accepted in input paths and converted to the platform standard
- Maximum path length: Long path handling follows .NET runtime defaults

**VSS Path Resolution**
When the `--vss` flag is used, file access is redirected through Volume Shadow Copy Service:
- The volume containing the root directory is snapshotted
- Original file paths are translated to VSS snapshot paths using `VssPathResolver`
- Files are accessed through their snapshot paths, allowing verification of locked files
- The snapshot is automatically cleaned up after operation completion

The following diagram illustrates the path resolution workflow:

``mermaid

## Glob Pattern Matching

Glob pattern matching is implemented using the `GlobUtils` class, which provides consistent filtering behavior across all commands.

**Pattern Normalization**
- Input glob strings are split on semicolons (`;`) to support multiple patterns
- Empty or whitespace-only patterns are trimmed
- For include patterns: empty input defaults to `**/*` (match all files)
- For exclude patterns: empty input defaults to no exclusions


```csharp
public static string[] NormalizeGlobs(string? globs, bool isExclude = false)
{
    if (string.IsNullOrWhiteSpace(globs))
        return isExclude ? [] : ["**/*"];
    return globs.Split(';', StringSplitOptions.RemoveEmptyEntries | StringSplitOptions.TrimEntries);
}
```


**Matching Logic**
- Matching is case-insensitive across all platforms
- The `IsMatch` method evaluates both include and exclude patterns:
  - A file must match at least one include pattern (or the default `**/*`)
  - A file must not match any exclude pattern
- Patterns use standard glob syntax:
  - `*` matches any sequence of characters within a single directory
  - `**` matches any sequence of directories (recursive)
  - `?` matches any single character

**Filtering Process**
The `FilterFiles` method applies glob patterns to a collection of file paths:

``mermaid

A["Input Files"] --> B["Create Matcher"]

C --> D["Add Exclude Patterns"]
D --> E["Execute Matching"]
E --> F["Normalize Path Separators"]
F --> G["Calculate Relative Paths"]
G --> H["Return Matched Files"]

```

## Volume Shadow Copy Service (VSS) Support

The `--vss` argument enables Volume Shadow Copy Service (VSS) support, allowing Verity to create snapshots of volumes and access files that might otherwise be locked or in use.

**VSS Architecture Components**
- `VssSnapshotManager`: Manages the lifecycle of VSS snapshots, including creation and cleanup
- `VssPathResolver`: Translates original file paths to their corresponding VSS snapshot paths
- `ElevationHelper`: Handles UAC elevation requirements for VSS operations

**Operation Workflow**
1. When `--vss` is specified, the application checks for administrator privileges
2. If not elevated, the application automatically requests elevation
3. The volume containing the root directory is snapshotted
4. A `VssPathResolver` is created to translate file paths
5. All file operations are redirected to use the snapshot paths
6. After completion, the snapshot is automatically cleaned up

**Elevation Requirements**
VSS operations require administrator privileges:
- If the application is not running with elevation, it will automatically prompt for elevation
- If elevation is declined, the operation fails with exit code 100 (`ElevationRequired`)
- The elevation request is handled by `ElevationHelper.RestartElevatedAsync`

**Error Handling**
VSS operations can fail with specific error codes:
- `ElevationRequired` (100): Application needs administrator privileges
- `VssNotAvailable` (101): VSS is not available on the system
- `SnapshotCreationFailed` (102): Failed to create the VSS snapshot
- `VolumeNotSupported` (103): The volume does not support VSS snapshots

## Practical Usage Examples

**Verifying a Manifest**
```
bash
verity verify checksums.sha256 --root ./project --algorithm SHA256 --include "*.dll;*.exe" --exclude "*.pdb"

```
This command verifies all `.dll` and `.exe` files in the `./project` directory against the `checksums.sha256` manifest, excluding `.pdb` files.

**Creating a Manifest for Nested Directories**
```
bash
verity create docs.sha256 --root ./documentation --include "**/*.md;**/*.txt"

```
Creates a manifest for all Markdown and text files in the `./documentation` directory and its subdirectories.

**Adding Files with Custom Base Path**
```
bash
verity add assets.sha256 --root /var/www/static --include "images/*.png;scripts/*.js" --tsv-report errors.tsv

```
Adds new PNG images and JavaScript files from `/var/www/static` to the existing `assets.sha256` manifest and writes error details to `errors.tsv`.

**Using VSS Mode to Verify Locked Files**
```
bash
verity verify system.sha256 --root C:\Windows\System32 --vss

```
Verifies checksums against files in the System32 directory, using VSS to access files that might be locked by the operating system. This command will automatically request administrator privileges.

**Creating a Manifest from a VSS Snapshot**
```
bash
verity create backup.sha256 --root D:\Data --include "**/*.docx;**/*.xlsx" --vss
```
Creates a manifest of all Office documents from the D: drive using a VSS snapshot, ensuring consistency even if files are being modified during the operation.

**Difference Between --root and Positional Path**
- The positional path (e.g., `checksums.sha256`) refers to the manifest file itself
- The `--root` parameter specifies the directory context for interpreting paths within the manifest
- When `--root` is omitted, the manifest file's directory serves as the root
- The `--vss` parameter affects how files are accessed, redirecting operations through VSS snapshots when enabled

For example, with a manifest at `/home/user/manifest.txt` containing `data/file.txt`:
- Without `--root`: resolves to `/home/user/data/file.txt`
- With `--root /opt/app`: resolves to `/opt/app/data/file.txt`
- With `--vss`: accesses files through a VSS snapshot of the volume containing the root directory

## Special Character Escaping in Glob Patterns

Glob patterns in Verity follow standard Microsoft.Extensions.FileSystemGlobbing behavior:

**Special Characters**
- `*` - Matches any sequence of characters (except path separators)
- `**` - Matches any sequence of characters including path separators (recursive)
- `?` - Matches any single character
- `[abc]` - Matches any single character in the set
- `[a-z]` - Matches any single character in the range

**Escaping Rules**
- Special characters do not need to be escaped in most cases
- To match a literal `*`, use `[*]`
- To match a literal `?`, use `[?]`
- Brackets `[ ]` are only special when used for character classes
- Backslashes are not used for escaping; use character classes instead

**Best Practices**
- Use semicolons to separate multiple patterns rather than complex single patterns
- Be specific with patterns to avoid unintended matches
- Test patterns with `--showTable` to verify which files are included/excluded
- Remember that matching is case-insensitive on Windows
