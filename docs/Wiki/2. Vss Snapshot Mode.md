## Introduction
VSS Snapshot Mode is a feature within the Verity application that enables file integrity verification and manifest creation using Volume Shadow Copy Service (VSS) snapshots. This capability allows the application to access files that may be locked or in use by other processes by creating a point-in-time snapshot of the volume. The implementation leverages the AlphaVSS library to interface with Windows VSS, providing reliable access to file system states without interfering with active processes.

This documentation provides a comprehensive overview of the VSS Snapshot Mode implementation, including its architecture, core components, API interfaces, integration patterns, and practical usage examples. The system is designed to handle elevation requirements, snapshot lifecycle management, and path resolution to enable seamless access to shadow-copied files.

## Core Components
The VSS Snapshot Mode implementation consists of three primary components that work together to provide snapshot functionality: VssSnapshotManager, VssPathResolver, and ElevationHelper. These components handle snapshot creation, path translation, and privilege management respectively.

The VssSnapshotManager class is responsible for creating and managing VSS snapshots, implementing IDisposable to ensure proper cleanup. The VssPathResolver translates original file paths to their corresponding locations within the snapshot. The ElevationHelper manages the privilege requirements for VSS operations, automatically requesting elevation when necessary.

## Architecture Overview
The VSS Snapshot Mode architecture follows a layered approach with clear separation of concerns. The system begins with command-line interface detection in `Program.Main`, which calls `ElevationHelper.EnsureElevatedAsync` when VSS mode is requested. If the process is not elevated, the command is relaunched elevated (UAC) in its own console window with the hidden marker argument `--verity-elevated-child`; the parent waits and exits with the child's exit code. In the (elevated) process that runs the command, the `VssSetup` phase of the run pipeline (`RunPipeline.VssSetupAsync`) creates the volume snapshot with VssSnapshotManager using the AlphaVSS library, and the VssPathResolver provides transparent path translation: hashing **and** all file enumeration (size tally, create/add scan, "file not in manifest" check) read the snapshot, while reported paths remain the original ones.

### VssPathResolver Analysis
The VssPathResolver component handles the translation of original file paths to their corresponding locations within the VSS snapshot. This enables transparent access to files in the snapshot without requiring changes to file processing logic.

For enumeration, `ResolveDirectoryPath` maps a directory and always returns it with a trailing separator, because a snapshot device root (`\\?\GLOBALROOT\Device\HarddiskVolumeShadowCopyN`) cannot be enumerated without one. `RunContext.ScanRoot` uses it, so in VSS mode the size tally, the create/add scan and the "file not in manifest" check all enumerate the snapshot rather than the live volume.

### ElevationHelper Analysis
The ElevationHelper class manages the privilege requirements for VSS operations, automatically handling the elevation process when required. `EnsureElevatedAsync` returns an `ElevationResult` whose `ElevationOutcome` is `NotRequired`, `AlreadyElevated`, `Relaunched` (carrying the child's exit code), `Declined` or `Failed`. `Main` continues only for the first two; on `Relaunched` it exits with the child's exit code, on `Declined`/`Failed` with `100` (ElevationRequired). The elevated child receives the marker `--verity-elevated-child` (`ElevationHelper.ElevatedChildMarker`), which `Main` strips before parsing; the child never tries to elevate again and, if stdin is interactive, waits for a key press before its window closes. Arguments are quoted by `EscapeArgument` following the Windows `CommandLineToArgvW` rules (including trailing backslashes).

## Integration Patterns
The VSS Snapshot Mode is integrated into the Verity application through command-line options and programmatic configuration. The system follows a consistent pattern across different commands (verify, create, add) to enable VSS functionality.

## Practical Examples

### Basic Usage
To use VSS Snapshot Mode, simply add the --vss flag to any Verity command:

```
bash
# Verify files using VSS snapshot
verity verify manifest.txt --vss

# Create manifest using VSS snapshot
verity create new_manifest.txt --vss

# Add files to manifest using VSS snapshot
verity add existing_manifest.txt --vss

```

### Programmatic Implementation
Here's an example of how to use the VSS components programmatically:

```
csharp
try
{
    // Determine volume to snapshot
    var rootPath = options.RootDirectory?.FullName ?? options.ChecksumFile.DirectoryName!;
    var volumeRoot = Path.GetPathRoot(rootPath);
    
    if (string.IsNullOrEmpty(volumeRoot))
    {
        Console.WriteLine("Error: Unable to determine volume root for VSS snapshot.");
        return (int)VssErrorCode.VolumeNotSupported;
    }
    
    // Create and use VSS snapshot
    using var vssManager = new VssSnapshotManager(volumeRoot);
    await vssManager.CreateSnapshotAsync();
    
    // Create path resolver for translating paths
    var vssResolver = vssManager.CreatePathResolver();
    
    // Process files using snapshot paths
    foreach (var file in filesToProcess)
    {
        var snapshotPath = vssResolver.ResolvePath(file.OriginalPath);
        // Process file at snapshotPath
        var hash = ComputeHash(snapshotPath);
    }
}
catch (VssSnapshotException ex)
{
    Console.WriteLine($"VSS Error: {ex.Message}");
    return (int)VssErrorCode.SnapshotCreationFailed;
}
catch (OperationCanceledException)
{
    Console.WriteLine("Interrupted by user");
    return -2; // ExitCodes.Interrupted
}

```

### Error Handling Patterns
The VSS implementation includes comprehensive error handling for common scenarios:

```
csharp
// Handle elevation requirements
var elevation = await ElevationHelper.EnsureElevatedAsync(args, elevationRequired: true);
switch (elevation.Outcome)
{
    case ElevationOutcome.Relaunched:
        Environment.Exit(elevation.ExitCode!.Value); // the elevated child's result
        break;
    case ElevationOutcome.Declined:
    case ElevationOutcome.Failed:
        Environment.Exit((int)VssErrorCode.ElevationRequired); // 100
        break;
}

// Handle snapshot creation with timeout
try
{
    using var vssManager = new VssSnapshotManager(volumeRoot, TimeSpan.FromMinutes(2));
    await vssManager.CreateSnapshotAsync(cancellationToken);
}
catch (VssSnapshotException ex) when (ex.Message.Contains("timed out"))
{
    Console.WriteLine("Snapshot creation timed out. The volume may be under heavy load.");
}
catch (OperationCanceledException)
{
    // Ctrl+C: PrepareForBackup / DoSnapshotSet are interrupted and rolled back
}
catch (VssSnapshotException ex)
{
    Console.WriteLine($"Failed to create snapshot: {ex.Message}");
}

```

## Troubleshooting Guide
This section addresses common issues encountered when using VSS Snapshot Mode and provides solutions for each scenario.

### Elevation Issues
**Problem**: Application fails to create VSS snapshot with access denied errors.

**Solution**: Ensure the application is running with administrator privileges. When using the --vss flag, the application will automatically request elevation and run the command in a new elevated console window. If the UAC prompt is declined (or the relaunch fails), the process exits with code `100` (ElevationRequired).

```
csharp
// Check elevation status
if (!ElevationHelper.IsElevated())
{
    Console.WriteLine("Application requires administrator privileges for VSS operations.");
}

```

### Snapshot Creation Failures
**Problem**: VssSnapshotManager.CreateSnapshotAsync() throws VssSnapshotException.

**Common Causes and Solutions**:
- **Timeout**: The default timeout is 5 minutes. Because `PrepareForBackup` and `DoSnapshotSet` use the asynchronous AlphaVSS calls with the cancellation token, the timeout (and Ctrl+C) actually interrupt them. A timeout surfaces as a `VssSnapshotException` ("timed out", exit code `102`); a user cancel as `OperationCanceledException` (exit code `-2`). Increase the timeout or ensure the system is not under heavy load.
- **Volume not supported**: Some volume types (e.g., network drives) do not support VSS snapshots.
- **Insufficient disk space**: Ensure adequate free space for shadow copies in the system settings.

```
csharp
// Handle timeout specifically
var vssManager = new VssSnapshotManager(volumeRoot, TimeSpan.FromMinutes(10));

```

### Path Resolution Issues
**Problem**: Resolved snapshot paths do not point to valid files.

**Solution**: Verify that the original path is on the same volume as the snapshot. The VssPathResolver only translates paths for the snapshotted volume.

```
csharp
// Check if path is on snapshot volume
var resolver = new VssPathResolver(snapshotPath, volumeRoot);
if (resolver.IsPathOnSnapshotVolume(originalPath))
{
    var snapshotPath = resolver.ResolvePath(originalPath);
    // Path is valid for snapshot access
}
else
{
    // Path is on different volume, use original path
    var originalPath = Path.GetFullPath(originalPath);
}

```

### Resource Cleanup
**Problem**: VSS snapshots not being properly cleaned up.

**Solution**: Always use VssSnapshotManager within a using statement to ensure proper disposal:

```
csharp
using var vssManager = new VssSnapshotManager(volumeRoot);
await vssManager.CreateSnapshotAsync();
// Snapshot automatically cleaned up when disposed
```

The VssSnapshotManager implements IDisposable and will clean up the snapshot when disposed, even if an exception occurs. In the CLI, `RunPipeline.RunAsync` disposes the manager in a `finally` block whichever way the pipeline leaves. A failed creation rolls itself back immediately (`AbortBackup` if the snapshot set was started but not committed, `DeleteSnapshotSet` once committed) and the manager returns to `New`. Cleanup warnings are written to stderr so redirected stdout stays clean.

## Conclusion
VSS Snapshot Mode provides a robust solution for accessing locked or in-use files through Volume Shadow Copy Service snapshots. The implementation is well-structured with clear separation of concerns between snapshot management, path resolution, and privilege handling.

Key features include:
- Automatic elevation handling for administrative privileges
- Asynchronous snapshot creation with timeout support
- Transparent path translation for seamless file access
- Proper resource cleanup through IDisposable pattern
- Comprehensive error handling for common failure scenarios

The system integrates smoothly with the Verity application through command-line flags and can also be used programmatically for custom workflows. By leveraging the AlphaVSS library, the implementation provides reliable access to VSS functionality while abstracting away the complexity of the underlying Windows APIs.

For optimal use, ensure the application is run with appropriate privileges, handle exceptions appropriately, and always use proper disposal patterns to prevent resource leaks.
