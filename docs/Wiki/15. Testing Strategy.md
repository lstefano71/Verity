## Testing Strategy Overview

The Verity application implements a comprehensive testing strategy that follows the test pyramid model, combining unit tests for isolated utilities with integration tests for end-to-end command workflows. The test suite is built on the xUnit framework and organized to ensure high code coverage, maintainable test code, and reliable verification of both functional and non-functional requirements. The testing approach emphasizes realistic integration testing by executing the actual Verity.exe application through process invocation, ensuring that command-line interfaces, file system interactions, and overall application behavior are thoroughly validated. The strategy has been extended to include comprehensive testing of Volume Shadow Copy Service (VSS) functionality and elevation handling, ensuring reliable operation in elevated contexts.

#### CommandTestBase

The `CommandTestBase` class serves as the foundation for all command integration tests, providing a consistent lifecycle management and access to shared test fixtures.


```csharp
public abstract class CommandTestBase : IAsyncLifetime
{
  protected readonly CommonTestFixture fixture;
  public CommandTestBase(CommonTestFixture fixture)
  {
    this.fixture = fixture;
  }

  public async Task InitializeAsync()
  {
    if (Directory.Exists(fixture.TempDir)) {
      Directory.Delete(fixture.TempDir, true);
    }
    Directory.CreateDirectory(fixture.TempDir);
    await Task.CompletedTask;
  }

  public async Task DisposeAsync()
  {
    await Task.CompletedTask;
  }
}
```


This base class ensures that each test starts with a clean temporary directory and properly disposes of resources after execution.

#### CommonTestFixture

The `CommonTestFixture` class provides shared resources and utilities across all tests, implementing both `IAsyncLifetime` and `IDisposable` for proper resource management.

Key features include:
- **Temporary Directory Management**: Creates a unique temporary directory for each test run
- **Test File Creation**: Methods to create, modify, and delete test files
- **Manifest Management**: Utilities to create manifests with specified entries
- **Process Execution**: `RunVerity` method to execute the Verity application and capture results
- **Hash Calculation**: Helper methods for MD5 and SHA256 hash calculation

The fixture's `RunVerity` method is particularly important as it locates the compiled Verity.exe from the build output and executes it with specified arguments, capturing standard output, standard error, and exit codes for assertion.

### File System Mocking

Rather than using traditional mocking frameworks, the tests employ a "real filesystem in isolation" approach:

- Each test uses a dedicated temporary directory
- Files are created, modified, and deleted as needed
- The actual Verity.exe process interacts with these real files
- Assertions are made against the resulting file system state

This approach provides higher fidelity testing than pure mocking while maintaining isolation through directory separation.

### TSV Report Parsing

The `TsvReportParser` class enables verification of structured output:

```csharp
public static List<TsvReportRow> Parse(string tsvContent)
{
    var rows = new List<TsvReportRow>();
    var lines = tsvContent.Split(['\r', '\n'], StringSplitOptions.RemoveEmptyEntries);
    var dataLines = lines.Where(l => !l.StartsWith('#'));
    foreach (var line in dataLines) {
      var parts = line.Split('\t');
      if (parts.Length == 5) {
        rows.Add(new TsvReportRow(
            Status: parts[0],
            File: parts[1],
            Details: parts[2],
            ExpectedHash: parts[3],
            ActualHash: parts[4]
        ));
      }
    }
    return rows;
}
```


This utility allows tests to parse and assert on the detailed diagnostic reports generated by the application.

## Writing New Tests

### Extending Unit Tests

To add new unit tests for utilities:

1. Create a test class in the appropriate location
2. Use `[Fact]` for single scenario tests or `[Theory]` with `[InlineData]` for parameterized tests
3. Follow the arrange-act-assert pattern
4. Ensure tests are fast and have no external dependencies

Example template:

```csharp
public class NewUtilityTests
{
    [Fact]
    public void MethodName_Scenario_ExpectedBehavior()
    {
        // Arrange
        var input = /* test data */;
        
        // Act
        var result = NewUtility.Method(input);
        
        // Assert
        Assert.Equal(expected, result);
    }
}
```


### Creating Integration Tests

To add new integration tests:

1. Create a new test class that inherits from `CommandTestBase`
2. Inject `CommonTestFixture` through the constructor
3. Use the fixture's utilities to set up test conditions
4. Execute Verity commands using `RunVerity`
5. Assert on exit codes, file system state, and output artifacts

Example template:

```csharp
public class NewCommandTests : CommandTestBase, IClassFixture<CommonTestFixture>
{
    public NewCommandTests(CommonTestFixture fixture) : base(fixture) { }

    [Fact]
    public async Task CommandName_Scenario_ExpectedBehavior()
    {
        // Arrange
        fixture.CreateTestFile("test.txt", "content");
        
        // Act
        var result = await fixture.RunVerity("command args");
        
        // Assert
        Assert.Equal(0, result.ExitCode);
        // Additional assertions
    }
}
```
